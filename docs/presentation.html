Cómo construí

DroiDesk

Un sistema de tickets de soporte para una organización de ~800 personas, que construí con IA guiada por especificaciones: decido el qué y los agentes, el cómo.

10 fases · 10 PR 11 ADL 1.700+ tests 1 comando de setup

Claude Code · Opus 5.5 planifica · Sonnet 5.5 codifica · deckard revisa

01 · Punto de partida

Análisis del prompt inicial

Qué le pedí al agente

  • Producto: el MVP del enunciado (4 obligatorios + hasta 2 opcionales), con el look de un droide.
  • Método: spec-driven, design logs, revisión de deckard, Clean Code, SOLID y "Less is More".
  • Proceso: un bloque por user story, resumen y aprobación antes de cada commit; trunk-based, una rama y un PR por fase.
  • Técnica: front y back como apps separadas, SQLite hoy y PostgreSQL al escalar, Docker en un comando, context7.
  • Modelos: Opus 5.5 Max para planificar, Sonnet 5.5 xHigh para codificar.
  • Evidencia: DEV-LOG por hook, DECISIONS, AI-USAGE, README con Mermaid y 3 estrategias de escala.

Trunk-based con una rama por fase

  • Cada fase parte de origin/main actualizado, nunca de la fase anterior.
  • Un PR por fase, con CI en verde; lo integro con squash and merge: un commit por fase.
  • Sin push directo a main. Commits Conventional en español neutro.
  • Ningún subagente escribe en git: commit y push solo con aprobación.
04 · Orquestación

Subagentes y hooks

Un bloque, de punta a punta

Cada prompt de subagente lleva las tareas, las rutas, los contratos y las reglas: prohibido escribir en git, editar docs o tocar Docker ajeno. La regla de Docker la agregué tras un incidente real: un subagente borró la caché global de build de la máquina.

devlog.py · del repo

Escucha 7 eventos de Claude Code y escribe DEV-LOG.md: prompt, herramientas, archivos, commits, subagentes, tokens y hit de caché. Oculta secretos y respeta #nolog.

deckard · Stop

No deja cerrar un turno con código sin revisar sobre el estado actual.

rtk · PreToolUse

Reescribe cada comando de shell para comprimir su salida.

graft · SessionStart

Inyecta el mapa del repo y sugiere por dónde empezar a leer.
